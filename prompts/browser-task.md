# Browser Use実習：公開Issueを根拠付きで整理する

## 前提

- 対象は現在開いている公開教材リポジトリ
- GitHubへのログインは不要
- Issueの作成・コメント・編集はしない
- 外部サイトへの転載やアップロードはしない

## AIへの依頼例

```text
現在開いている公開教材リポジトリのIssue一覧を調べてください。

1. OpenのIssueを重要度別に数える
2. severity:S1またはseverity:S2でOpenのIssueを一覧にする
3. 内容が重複している可能性がある組を探す
4. kind:bugまたはkind:questionに限り、再現手順、期待結果、証跡の内容が「未記載」と明記されているIssueを探す。kind:test-gapはこの判定から除外する
5. 各判断についてIssue番号、タイトル、URL、根拠を表にする

推測した内容は事実として書かず、「候補」と明記してください。
GitHub上の情報を変更しないでください。
```

## 完了条件

- Issue番号とURLがある
- OpenとClosedが区別されている
- 重複は断定せず「重複候補」としている
- `kind:bug`または`kind:question`だけを情報不足の判定対象にしている
- 各見出しが「未記載」と明記されたものだけを情報不足としている
- 最後に取得日時を記載している

## うまく動かない場合

GitHub画面を取得できない場合は、`data/issues_snapshot.json`をブラウザで開くかダウンロードし、同じ依頼を実行します。その場合は「GitHubの現在状態ではなく、教材スナップショットを分析した」と明記します。
